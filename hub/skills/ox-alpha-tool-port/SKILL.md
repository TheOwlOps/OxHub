# OX Alpha Tool Port

Port Hermes Python `tools/*.py` + `toolsets.py:_HERMES_CORE_TOOLS` + `plugins/web/*` to OX Alpha `skills/src/builtin/*.ts` as `AgentTool`.

## Concepts

- **AgentTool (`*.ts`)** = executable capability the agent invokes through `AgentLoop` (lives under `skills/src/builtin/<group>/` as TS). **SKILL.md** = declarative procedural knowledge loaded via `loader.ts` front-matter parser — user-defined skills are discovered as `**/*.md` under `custom_dir` only; builtin `*.ts` AgentTools load statically via the `skills/src/index.ts` barrel and never go through `discoverSkills`. OX is hybrid: keep heavy executable logic in TS, expose reusable prompting workflows as `SKILL.md` with front-matter (`name`, `description`, `version`, `triggers`, `actions`). Porting Hermes tools means writing `*.ts`; write a SKILL.md only for a reusable workflow that needs prompting discipline, never as a wrapper around a single tool call. Delete demo stubs like `hello.ts` — they collide in the barrel (`TS2308` duplicate `skill` export) and add no value.

## When to Use

- User asks to add Hermes-like tools to `D:/ox-alpha`
- `skills/src/builtin/` has only stubs (`file-ops.ts`, `shell.ts`, `web-search.ts`) and `docs/tool-gap-inventory.md` is missing or stale
- Gateway `router.ts` AgentLoop is missing tool groups present in `_HERMES_CORE_TOOLS`
- Debugging desktop client connectivity after port changes (e.g. tracking shortcut `.lnk` to installed bundle in `%LOCALAPPDATA%\Programs`)

## Prerequisites

- Hermes repo at `C:/Users/OS/AppData/Local/hermes/hermes-agent/` (source of truth for `toolsets.py` + `tools/*.py`)
- OX Alpha at `D:/ox-alpha` (`pnpm 9`, `Node >=20`, workspace `@ox/*`, `skills/tsconfig.json` + `gateway/tsconfig.json` extend `tsconfig.base.json` with `noUnusedLocals`, `noUncheckedIndexedAccess`)
- `AgentTool` interface from `packages/ai/src/agent.ts`: `{name, description, parameters, execute}` — `tools.ts` holds only `ToolDefinition/ToolCall/ToolResult`; importing `AgentTool` from `./tools.js` fails with `TS2305 has no exported member`

## Procedure

### 0. Inventory first (Phase 1) — never code before the gap file

1. Read `toolsets.py:_HERMES_CORE_TOOLS` (53 tools) and `tools/*.py` file list.
2. Read `D:/ox-alpha/skills/src/builtin/*.ts` and `skills/src/index.ts` exports.
3. Write `D:/ox-alpha/docs/tool-gap-inventory.md` with: Hermes count, OX existing table (file + status OK/weak/custom), missing list, Phase 2 priority order. Phase 2 order user expects: `web_search+web_extract` → `terminal+process_manage` → `patch+search_files` → `browser_*+browser_exec` → others.

### 1. Implement a tool group (Phase 2) — one file per group

1. Create `skills/src/builtin/<group>-tools.ts` (e.g. `web-tools.ts`, `terminal-tools.ts`). Each file exports one `AgentTool` const per tool + an array (`webTools`, `terminalTools`). When `builtin/` exceeds ~15 files, group into subdirs (`core/`, `file/`, `web/`, `agent/`, `media/`, `infra/`) instead of flat files — shared helpers (e.g. `tool-context.ts`) live in `core/` and siblings import via `../core/tool-context.js`; update `skills/src/index.ts` export paths per group after moving, then rebuild.
2. Mark deliberate ceilings with `ponytail: ceiling is X. Upgrade path: Y` comment (e.g. DDG HTML scrape / fetch+htmlToText ceiling, upgrade Firecrawl/Exa/Playwright when keys/need arise).
3. No new deps — use `fetch`, `node:fs/promises`, `node:child_process`, `path`. SSRF filter: block `http` only, private hosts (`localhost`, `127.0.0.1`, `10.*`, `192.168.*`, `172.16-31.*`, `*.local`).

**web_extract recipe:** `assertSafeUrl` → `AbortController` 15s → `fetch` → check `content-type` → `htmlToText` (strip script/style/tags, decode entities) → `truncate(limit*0.7 head + tail)` → `results.push({url,title,content,error,truncated})`. Max 5 URLs.

**terminal+process_manage recipe:** Module-level `Map<string,ProcessEntry>` + `nextProcId`. `terminal`: validate `command`, block `rm -rf /`, `format c:`, `del /f /s /q c:\`, `mkfs.`; resolve `cwd`; if `background` spawn with `shell:true`, store entry, return `session_id`; else spawn foreground, collect `chunks`, `setTimeout` kill `SIGTERM`→`SIGKILL`, concat + truncate 40k. `process_manage`: `list|poll|log|kill` via `session_id`.

### 2. Export and wire

1. Add `export * from './builtin/<group>-tools.js';` to `skills/src/index.ts`.
2. In `gateway/src/router.ts`: import new arrays and spread into `new AgentLoop(router, [...fileOpsTools, ...shellTools, ...webSearchTools, ...webTools, ...terminalTools])`.
3. For batch ports, fan out with `delegate_task` (up to 5 parallel leaf tasks, one tool group per task) — but run `ls skills/src/builtin/` BEFORE dispatching and skip already-ported groups; duplicate dispatch wastes the batch and risks conflicting overwrites.
4. Never let two subagents patch the same shared file (`skills/src/index.ts`, `gateway/src/router.ts`) concurrently — concurrent edits produce stale-`old_string` patch failures. Wire centrally after all children finish, or require each child to re-read the file immediately before patching and merge siblings' additions.
5. Every child must prove its write with a read-back (`read_file` showing the new file, or a clean `tsc` build) — a completion claim without a verifiable file handle is not done; re-dispatch or finish it directly. State the absolute workspace path (`D:/ox-alpha/...`) in each task context — a bare relative `skills/src/builtin` resolves against the wrong cwd and lands files outside the repo.

### 3. Context + gateway backend (Phase 3) — model context, session, adapters, delivery, providers

1. Model context display: create `skills/src/builtin/tool-context.ts` with `setCurrentModel`, `enrichWithContext(json)` (appends `_ctx` with model + est tokens), no unused imports. Wrap every tool success return as `enrichWithContext(JSON.stringify({...}));` — count parens (`}));`), then `npx tsc --project skills/tsconfig.json --noEmit` and fix `TS6133` unused imports immediately.
2. Agent verbose header: add `verbose?: boolean` to `AgentRunOptions`; annotate only the injected `<tool_response>` message content with `<<context:model=X | turn=N | tool=T | est_tokens=E>>`, keep raw string in `ToolResult.result` so stored history stays clean.
3. Session persistence: schema + repo live in `packages/db` (`sessions`, `transcripts`/`messages`, `delivery_ledger`); gateway `session-manager.ts` must import the REAL export name from `@ox/db` — read `packages/db/src/index.ts` first (`getSessionStore` vs `getSessionRepo` mismatch breaks the build).
4. Robust adapters: `gateway/src/adapters/base-adapter.ts` holds TokenBucket + CircuitBreaker + `retryWithBackoff` + delivery map; logger must be a plain literal (`createLogger('adapter')`) — never reference abstract `this.name` in a field initializer (`TS2715`/`TS2729`/`TS2742`). Remove unused `lastFailTime` (`TS6133`).
5. Delivery ledger: import schema from `@ox/db`, never `@ox/db/schema`; never import `drizzle-orm` directly in gateway unless it is a declared gateway dep — use re-exports from `@ox/db`.
6. Real providers: `CredentialPool` round-robins keys per provider; `ProviderRouter.generate` walks `[primary, ...fallbacks]` and returns first success. A provider returning canned strings is fake — real one `fetch`es the vendor API with `pool.getKey()` and maps messages to vendor format.
7. Delegation (Hermes `delegate_task` port): create `packages/ai/src/delegation.ts` with `DelegationManager` (isolated child `AgentLoop` per task, chunked by `maxConcurrent`, `background` jobs pollable via `getJob`), `createDelegateTool(manager)` factory, plus `DelegationTask/Result` types; export from `packages/ai/src/index.ts`. In `gateway/src/router.ts` construct in order — `AgentLoop` first, then `new DelegationManager(modelRouter, agentLoop.getTools())`, then `agentLoop.registerTool(createDelegateTool(manager))` so the main agent self-delegates. Add `gateway/src/routes/delegate.ts` (`POST /`, `GET /`, `GET /:id`) and mount with `app.route('/api/delegate', ...)` in `server.ts`. Orchestrator children get a nested `delegate_task` bound to depth+1; leaf children filter it out; cap depth (default 2).

### 4. Verify (real build, not per-file tsc)

```bash
pnpm --filter @ox/ai build       # tsc for ai first (gateway+skills resolve it from dist/)
pnpm --filter @ox/skills build   # tsc for skills
pnpm --filter @ox/gateway build  # tsc for gateway (ensures @ox/skills import resolves)
```
Alternative gate: `npx tsc --project skills/tsconfig.json --noEmit` then `npx tsc --project gateway/tsconfig.json --noEmit`.

Fix until both exit 0.

## Pitfalls

- Desktop client path divergence on port change: When gateway/engine port changes (e.g. 1006 -> 1060), desktop applications launched from Windows shortcuts (`Desktop\OX Alpha.lnk`) run from `%LOCALAPPDATA%\Programs\<app>` or `Program Files`, NOT the repo build folder. Check and patch bundled assets (`resources.neu` or embedded dist) in the installed application directory or re-run installer.
- Duplicate export between `web-search.ts` and `web-tools.ts` both defining `webSearchTool`/`webSearchTools` — keep `webSearchTool` only in `web-search.ts`; `web-tools.ts` must export only `webExtractTool`/`webTools` until a unified file is planned. Registry duplicate is a build error (`TS2308`).
- `noUncheckedIndexedAccess` + strict nulls — regex `m[1]` is `string|undefined` — always use `(m[1] ?? '')` or `(m?.[1] ?? '')` before `.replace`/`.trim`; same for `limit - results.length` where limit may be undefined, default `limit=5`.
- `noUnusedLocals` — leftover `const shell = ...` after switching to `shell:true` spawn fails the build — delete unused bindings.
- Gateway imports fail as `has no exported member` while `skills` has built `dist/` — `gateway` resolves from `@ox/skills` workspace `dist/index.d.ts`, so build `skills` first then `gateway`.
- Background process registry must be module-scoped singleton `Map` in `terminal-tools.ts` — per-request map loses `poll`/`log` lookups.
- Never `pnpm add` playwright/puppeteer/tavily for the first port — stdlib fetch ceiling is the YAGNI default; add only on explicit user request.
- Bulk-wrapping returns with `enrichWithContext(JSON.stringify(...))` miscounts parens — the wrapped form needs `}));` (close object, close stringify, close enrich). Grep `enrichWithContext` after any regex rewrite and build `skills` before touching gateway.
- `tool-context.ts` must import only what it uses — unused `AgentLoop`/`createLogger` or unused `estimateTokens` in consumers fails on `noUnusedLocals` (`TS6133`).
- `BaseAdapter` logger cannot use `` `adapter:${this.name}` `` in a field initializer — abstract property access plus non-portable pino type fails the build; use a literal and specialize inside methods.
- Gateway backend imports: schema from `@ox/db` (not `@ox/db/schema`), no direct `drizzle-orm` import in gateway, and confirm the session repo export name in `packages/db/src/index.ts` before writing `session-manager.ts`.
- Fake vs real provider: round-robin `CredentialPool` + fallback-chain `ProviderRouter` + live `fetch` with the pooled key is real; canned-string returns are stubs — replace them, never ship them as done.
- Build order is `@ox/ai` → `@ox/skills` → `@ox/gateway`; gateway and skills resolve workspace deps from `dist/`, so a new export in `ai` is invisible until `ai` rebuilds — a `has no exported member` error on a just-added symbol usually means stale `dist`, not a bad import.
- Optional-key upgrade pattern (e.g. Firecrawl): gate on env (`FIRECRAWL_API_KEY` set → vendor API, unset → stdlib fetch fallback) so the tool works with zero config and only gets faster when the key exists — never hard-require a key for the first port.
- When chat reports 'All AI providers failed', check provider config before touching code: confirm root `.env` keys are loaded, then `curl <base_url>/v1/models` — an HTML response means the URL points at a dashboard page, not an OpenAI-compatible endpoint, and no router fix will help.
- After moving files into subdirs, every relative import gains one level (`../types.js` → `../../types.js`, `../registry.js` → `../../registry.js`) while sibling tool files keep shared helpers at `../core/<helper>.js` — rewrite the `skills/src/index.ts` barrel paths in the same pass and rebuild immediately, since stale paths fail with `TS2307`.
- Barrel `export *` collides when two files export the same name — two `SkillDefinition` stubs both exporting `skill` fail with `TS2308`. Keep only one same-named export per barrel: rename, scope the import, or delete demo stubs instead of shipping them.
- Do not add a `yaml` dependency for SKILL.md front-matter — a 10-line manual parser handling `key: value` plus JSON arrays covers `name/description/version/triggers/actions` without a new dep; keep the YAGNI ceiling and avoid version drift.
- When the user asks why skills are not `.md`, explain the hybrid: TS under `skills/src/builtin/` is `AgentTool` for `AgentLoop` loaded statically via the barrel; `.md` under `skills/<category>/<name>/SKILL.md` or `custom_dir` is declarative prompting discovered as `**/*.md` with front-matter. Do not convert a working AgentTool to MD just to satisfy the file extension.
- `loadSkillFromFile` must convert Windows paths to `file://` URLs before dynamic `import()` — a bare `D:/...` path fails with `ERR_UNSUPPORTED_ESM_URL_SCHEME` and makes every discovered skill report failure.
- When `web_extract` refuses a GitHub tree/API URL as SSRF-blocked, fetch the skill catalog with a shallow sparse git clone in scratch (`git clone --depth 1 --filter=blob:none --sparse` + `git sparse-checkout set <dir>`) then `find ... -name SKILL.md` locally instead of retrying the blocked fetch.
- Tri-Stack Architecture Boundary (Go + Python + TS): Structure the codebase 1:1 with Hermes domain layout: `agent/` (ReAct loop, compaction, steer), `gateway/platforms/` (Telegram, Discord, Zalo, Webhook), `cron/`, `skills/` (with Hub downloading from GitHub / index.json), `acp_adapter/` (IDE JSON-RPC), `providers/`, `state/` in Go for zero-runtime concurrency and native single-binary performance; heavy compute (`tools/python_workers/` for CDP headless browser `browser_exec`, document parsing, sandbox execution) in Python 3.11+ via stdio JSON-RPC; presentation layer (`web/`, `apps/desktop-wails/`) strictly in TypeScript React.
- Hermes Skills Hub Protocol: Centralized skills registry at `https://hermes-agent.nousresearch.com/docs/api/skills-index.json` combined with GitHub raw fetchers (`GitHubSource`) and open repositories (`agentskills.io`, `clawhub`, `lobehub`) allowing dynamic skill installations via slash command `/skills install <slug>` without daemon restarts.
- Native Multi-Platform Bot Adapters in Go: Telegram uses long-polling `getUpdates` with offset tracking over standard `http.Client`; Discord connects to `wss://gateway.discord.gg/?v=10` via `gorilla/websocket` with Opcode 1 Heartbeat ticker and Opcode 2 Identify, dispatching on `MESSAGE_CREATE`. Message handlers run in isolated goroutines with bounded timeouts (90s) calling `reactEngine.Run` without blocking gateway loops.
- Dynamic Skill Evolution in Go (`skill_manage`): The engine needs autonomous capability expansion (`CreateSkill`, `PatchSkill`, `DeleteSkill`) writing standard YAML frontmatter directly to `user-skills/<name>/SKILL.md` and refreshing the in-memory catalog under `sync.RWMutex` so the agent can learn and persist lessons across sessions without daemon restart.
- DuckDuckGo Instant API (`api.duckduckgo.com/?format=json`) returns empty for news, recent topics, and non-English queries; always scrape `https://html.duckduckgo.com/html/?q=` with Chrome User-Agent, extract `.result__snippet` and decode `uddg=` redirect URLs, keeping Instant API as fallback only.
- Discord channels lack native markdown table rendering — format scheduled reports and bot messages as bullet lists with markdown links `[Title](url)` instead of `| col | col |` tables.
- `skills/src/builtin/web/research.ts` tools (`duckduckgo_search`, `fetch_web_page`, `github_search`, `github_trending`, `arxiv_search`) must match `research.default_tools` in `ox.yml`; omitting tools disables them in default research loops.
- `github_trending` implementation trap: never use GitHub Search API (`stars:>500 pushed:>date sort=stars`) to fetch "trending" — that returns all-time highest-starred repos (freeCodeCamp, build-your-own-x) rather than current trending velocity. Must scrape `https://github.com/trending?since=daily` HTML directly for repo names, then parallel-fetch repo metadata from `api.github.com/repos/{name}` to enrich stars, language, and description.
- When serving the Web Dashboard SPA from gateway HTTP server, attach `Cache-Control: no-cache, no-store, must-revalidate` headers to both static assets and index.html fallbacks to prevent browsers from caching stale bundles after redesign builds. Browsers can still hold hard disk caches — instruct users to hard-reload (`Ctrl+F5` or DevTools "Empty Cache and Hard Reload") if UI updates do not appear immediately after rebuild.
- Tách thư mục user-skills khỏi package code (`user-skills/` thay vì `./skills` trong `ox.yml: custom_dir`) — để discoverSkills chỉ quét file `.md` người dùng, không bị nhầm lẫn với file `.ts` của package `@ox/skills`.
- Đặt tên thư mục user skills (`user-skills/<skill-name>/SKILL.md`): Dùng tên tiếng Anh chuẩn kebab-case (e.g. `nano-pdf`, `github-manager`, `blog-watcher`, `weather-lookup`, `summarizer`, `diagram-designer`) kèm metadata YAML frontmatter (`name`, `description`, `triggers`, `actions`), tránh dùng tiếng Việt không dấu để giữ giao diện và CLI nhất quán.
- Đa ngôn ngữ UI: dùng React Context lưu vào `localStorage('ox_lang')` với các locale chuẩn `vi` (mặc định), `en`, `zh`, `ja`, `ko`, `fr` — không dùng thư viện ngoài; thay triệt để chuỗi hardcoded trên toàn bộ page/component để tránh tình trạng giao diện nửa Anh nửa Việt. Tách toàn bộ từ điển sang các file JSON độc lập trong `app/i18n/locales/{code}.json`, để `app/web/src/lib/i18n.ts` làm loader thuần (~2KB) thay vì hardcode dictionary trực tiếp trong file TSX (>30KB). File TypeScript không chứa JSX thì giữ đuôi `.ts` và dùng `React.createElement`, tránh tạo nhầm `.tsx` gây trùng lặp file và lỗi TS2307/TS1005. Luôn gắn Language Switcher (select/button dropdown hiển thị cờ quốc kỳ) ở Sidebar footer hoặc Header để người dùng có thể chuyển đổi trực tiếp trên UI, tránh tình trạng code đã có mà người dùng không thấy chức năng.
- Dữ liệu trên UI phải đọc thật từ backend API: tuyệt đối không hardcode mock data (như danh sách MCP server chưa cài đặt hay trạng thái kênh cứng `ONLINE`) — hiển thị đúng trạng thái config thực tế qua `/api/status` và `/api/mcp`.
- MCP configuration trong `ox.yml`: Đồng bộ hai chiều giữa khai báo YAML (`mcp.servers`) và API gateway (`gateway/src/server.ts` `/api/mcp`). Khi kết nối thêm các MCP server ngoài (như `chrome-devtools`, `github`, `canva`, `clawlink`, `vercel`), cung cấp đầy đủ transport type (`builtin`, `stdio`, `oauth`, `sse`), trạng thái kết nối và danh sách công cụ thực tế.
- Electron App before-quit property: Không gán trực tiếp cờ boolean vào instance của Electron `app` (`app.isQuitting = true` gây lỗi compile `TS2339`), sử dụng biến module-level (`let isQuitting = false;`) để theo dõi trạng thái quit sạch sẽ.
- Chat UI UX controls: Thêm nút nổi 'Cuộn xuống cuối' (Scroll to Bottom) bằng cách lắng nghe `onScroll` trên container tin nhắn tính `distanceFromBottom = scrollHeight - scrollTop - clientHeight > 150`, cuộn mượt bằng `messagesEndRef.current?.scrollIntoView({ behavior: 'smooth' })`, tự động ẩn khi ở sát đáy để tránh che khuất tin nhắn mới nhất.
- Khi tích hợp kênh Zalo cho OX Alpha Gateway: không dùng Zalo OA webhook (đòi giấy phép kinh doanh, webhook public domain); kết nối trực tiếp vào local bridge server (`hermes-zalo-plugin` trên port `8787`) qua SSE `GET /events` (nhận tin) và REST `POST /send` `{ threadId, threadType, text }` (gửi tin), chú ý `threadId` phải nằm trong `ALLOWED_THREADS` của bridge.
- ZaloAdapter kế thừa `ChannelAdapter` (`@ox/protocol`) bắt buộc phải implement đủ abstract methods `connect()` và `disconnect()` (ngoài `start()`, `stop()`), nếu không TypeScript sẽ báo lỗi `TS2654: Non-abstract class is missing implementations for members 'connect', 'disconnect'`.
- Pattern mở rộng Multi-Provider LLM: Các provider chuẩn OpenAI-compatible (OpenRouter, Groq, Mistral, Together, xAI, Ollama) kế thừa trực tiếp từ `OpenAIProvider` trong `packages/ai/src/providers/openai-compatible.ts`; cần cập nhật đồng bộ 4 điểm: (1) `DEFAULT_PROVIDER_MODELS` và `isModelCompatibleWithProvider` trong `router.ts`, (2) auto-infer provider theo tên model trong `agent.ts`, (3) đăng ký instance + env key trong `gateway/src/router.ts`, và (4) danh sách model hiển thị trên Web UI `/api/models`. Rebuild `@ox/ai` trước khi rebuild `@ox/gateway`.
- YouTube/media link hallucination: LLMs fabricate plausible 11-char video IDs from memory (~50% are dead links, baby shark, or trailer trailers). Fix: add a `youtube_search` tool that scrapes `youtube.com/results?search_query=` and extracts real `videoId` from page JSON — never let the model generate video IDs from knowledge. Add anti-hallucination rule to `agent.ts` system prompt: "NEVER fabricate specific video IDs, article URLs, or download links from memory; MUST use tools or provide search-query fallback link."
- Two-Tier Anti-Hallucination Guardrail: Combining a system prompt constraint alone is insufficient because non-thinking or high-temperature models still output raw watch URLs directly in text. Implement an output sanitizer in `AgentLoop.run()`: if the assistant's final response contains `youtube.com/watch?v=` but `youtube_search` was never called during the session turns, automatically replace the hallucinated IDs with query links (`youtube.com/results?search_query=...`) before delivery.
- Slash Commands Execution Routing: Support instant slash commands (`/stop`, `/clear`, `/new`, `/trending [since]`, `/search`, `/youtube`, `/skills`, `/mcp`, `/status`, `/help`) at BOTH the frontend (`ChatWindow.tsx`) AND the gateway router backend (`handleIncomingMessage` in `router.ts`). When commands are typed via external adapters (Telegram, Zalo, CLI), intercept them at the router layer before pushing to `AgentLoop` or LLM to immediately execute lifecycle control (e.g. `AbortController.abort()` on `/stop`, memory wipe on `/clear`) and prevent AI hallucinations or token waste on system commands.
- Slash `/new` in Chat UI: Never bind `/new` or `/reset` to `createConversation()` which appends duplicate/empty conversation items in the sidebar list. Clear messages and reset context in the active conversation session in-place (`api.clearMessages(conversationId)`), matching Hermes and Discord `/new` behavior.
- User skills directory naming: Always name skill folders in `user-skills/` using standard English kebab-case (e.g. `nano-pdf`, `github-manager`, `blog-watcher`, `weather-lookup`, `summarizer`, `diagram-designer`) with YAML frontmatter, avoiding non-English or colloquial directory names.
- Skill Cards UI layout: Keep cards compact (`p-4`, toggle `w-8 h-4`) using Slate dark theme (`bg-slate-950/90` or `bg-slate-900/90`, `border-slate-800`). Limit descriptions to 2 lines (`line-clamp-2`), display up to 3 tools/triggers horizontally with `+N` overflow badges instead of multiline wrapping to prevent cards from stretching vertically.
- Native In-Process MCP Tooling pattern: Rather than spawning external MCP servers via stdio processes (which adds node/npx subprocess startup overhead, memory bloat, and Windows process lifecycle/lock issues), implement external MCP server tool specs (such as `github/github-mcp-server`) directly as native in-process `AgentTool` modules (e.g., `skills/src/builtin/web/github-mcp.ts`). Use native `fetch` with optional auth headers, export the tools array, and inject directly into `AgentLoop` in `gateway/src/router.ts`.
- Clawdbot Gateway UI Theme Pattern: Match the Clawdbot dark gateway aesthetic by styling Dashboard/Layout with Deep Obsidian Slate (`bg-slate-950`), a top 'Gateway Access' panel displaying the runtime endpoint (e.g. `http://127.0.0.1:1006`), an emerald pulse status badge (`● Connected`), and a 4-card Snapshot grid (Uptime, Active Skills, MCP Integrations, Scheduled Tasks) with compact font-mono metric labels.
- Custom AI / 9Router Provider Fallback: When using local custom proxies (e.g. 9Router at `http://localhost:20128/v1`), configure `customUrl` with fallback `http://localhost:20128/v1` and instantiate `OpenAIProvider(apiKey, baseURL, 'custom')`. Do not introduce duplicate provider classes across packages if `OpenAIProvider` already accepts `baseURL` and custom provider name; ensure `dist/` is rebuilt before checking gateway routing to avoid false provider initialization errors.

The buffer channel capacity should absorb bursts, and queue timeouts must be generous (e.g. 30–60s) or block on worker channel consumption.
- Go Agent Multi-Turn Working Memory Tool Sync: In agent loops (`Pipeline.ExecuteTurn`), ensure every intermediate LLM `respMsg` (with tool calls) and executed `ChatMessage{Role: RoleTool}` is committed to working memory (`AppendWorking`) alongside final user/assistant turns; appending only to local ephemeral loop slices causes subsequent sessions to lose all tool-call reasoning context.
- Scanner Buffer Allocation for Long Lines: `bufio.Scanner` defaults to 64KB max line length (`bufio.MaxScanTokenSize`). In filesystem tools (`read_file`), allocate a larger buffer via `scanner.Buffer(make([]byte, 64*1024), 10*1024*1024)` to avoid `bufio.Scanner: token too long` crashing on minified code or large JSON payloads.
- Test File Git Sanitation: When users request clean production repositories without test files, purge all `*_test.go` and update `.gitignore` (`*.test`, `*.out`, `*_test.go`) before staging commits to avoid orphan test artifacts in version control.
- Vite & Tailwind Unstyled Bundle Pitfall: When initializing a Vite + React + Tailwind frontend, creating `tailwind.config.ts` without `postcss.config.js` (with `tailwindcss` and `autoprefixer` plugins) silently skips CSS generation, rendering unstyled plain text. Furthermore, running `vite` dev server in headless/background subshells without a TTY fails immediately with `stdin is not a tty`. Build static bundles via `vite build` and serve via a lightweight HTTP server to guarantee reliable previews.
- Interactive Go CLI Tool Loading Parity: When building an interactive terminal REPL (`cmd/ox/main.go`), never instantiate only base filesystem tools. Wire the full tool suite (`web_search`, `web_extract`, `delegate_task` via subagent pool, `cronjob_manage`, `memory`) and configure terminal ANSI color themes so terminal-first workflows match gateway execution capabilities.
